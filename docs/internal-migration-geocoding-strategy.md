# 사내 데이터 이관 — 좌표/지오코딩 전략 (step 3)

> 전제(사용자 확정 2026-06-04): **운영망(금융사 폐쇄망)에서 외부 지오코딩 API 호출 불가.**
> 근거: 웹 3축(행안부 주소DB / 아파트 좌표 공공데이터 / 제공자 약관) + 로컬 2축(lat·lng 소비 코드 / Oracle 샘플 주소 포맷) 조사, critical 주장은 1차 출처로 적대 검증 완료.

## 0. 결론

지오코딩(주소→좌표 변환 **호출**)이 아니라 **공공 좌표DB 파일 반입 + 키 조인**으로 푼다.

1. 원천 = 행안부 **도로명주소 내비게이션용DB**(건물단위 좌표) 신청·반입, 월간 갱신.
2. 조인 키 = Oracle 단지 마스터에 이미 있는 **25자리 건물관리번호 `ROAD_NM_BLDG_MGMT_NO`** 정확 조인(1순위) → 구조화 키(2순위) → 풀주소 문자열(3순위).
3. 적재 = 수집기(newtech_data)에 좌표사전 테이블 + 조인 UPDATE 태스크(step2 §7의 `geocode_complexes_task` 자리). EPSG:5179→WGS84 변환 1회.
4. 외부망에서 미리 지오코딩해 결과를 반입하는 우회는 **약관상 봉쇄**(아래 §1) — 채택 금지.

## 2. 채택 원천 — 행안부 주소기반산업지원서비스 (juso.go.kr)

| 데이터셋 | 내용 | 검증 상태 |
|---|---|---|
| **내비게이션용DB** (1순위) | 건물단위 도로명주소 + 좌표 3종(건물중심점·주출입구·보조출입구는 6동 이상 집합건물). TXT, 시도별 **전체분+변동분**, 사실상 월간 | ✅ confirmed |
| 위치정보요약DB (경량 대안) | 도로명주소 + 주출입구 좌표만 | ✅ |
| GIS건물통합정보(국토부 15083092) | SHP 건물단위 좌표, '제한 없음' 직접 다운로드. 단 건물→단지 집계 필요 | ✅ (백업 원천) |
| SGIS 행정구역 경계 SHP | 무료 다운로드, 폴리곤 → centroid 산출 = 법정동 중심좌표 fallback 원천 | ✅ |

- **좌표계: 전부 EPSG:5179(UTM-K/GRS80)** → 앱은 WGS84(EPSG:4326) 사용 → 반입 적재 시 `pyproj` 변환 1회. ✅ confirmed
- **신청·승인 절차 필수**: 도로명주소법 시행령 46조·시행규칙 53조 — 신청서 작성 + 소관기관 이용목적 심사 후 다운로드. ✅ confirmed
- ⚠️ 라이선스 주의: data.go.kr 의 '제한 없음' 라벨만으로 사내 DB 적재·재가공 허용을 단정할 수 없음(적대검증에서 반박됨). **신청서 이용목적에 '사내 심사시스템 DB 적재' 명시**하고 승인 조건을 따른다.
- 참고: 아파트 "단지 식별자+좌표"를 한 파일로 직접 주는 공공 원천은 부재(K-apt 단지 기본정보 15073271 은 단지코드·주소만, 좌표 없음 — confirmed).

## 3. 조인 전략 (Oracle 샘플 19행 실측)

`CCTR_KB_APT_M` 샘플(61컬럼)에서 확인된 키 자원:

| 우선 | 키 | 근거 |
|---|---|---|
| **A** | `ROAD_NM_BLDG_MGMT_NO` (25자 건물관리번호, 예 `1111017400100230076000001`) | 행안부 건물 키와 **무가공 정확 조인**. 정규화·동음이의 없음 |
| B | 구조화 키: 시도 `CNP_NM` + 시군구 `CCW_NM` + 도로명(주소 4번째 토큰) + 본번 `ROAD_NM_BLDG_OGNO` + 부번 `ROAD_NM_BLDG_ASTNO` | KB가 이미 컬럼 분해해 둠. 부번 0 표기 정합 |
| C | 풀주소 문자열 `ROAD_NM_BSIC_ADDR` (형식 `시도 시군구 도로명 본번` 4토큰, 단지명 미포함 — 깨끗) | trim·연속공백 축약·부번 하이픈 처리 후 보조 경로 |

- 매칭 순서 A→B→C, 그래도 미스 → §5 fallback 결정.
- 지번 `STAD_CTNT` 는 비정형(`89외2필지` 등) → 조인 키 부적합, 보조 검증용만.
- **step2 사양 보강**: complex 추출 SELECT 에 `ROAD_NM_BLDG_MGMT_NO, ROAD_NM_BLDG_OGNO, ROAD_NM_BLDG_ASTNO` 3컬럼 추가.

## 4. 구현 설계 (수집기 newtech_data — step2 패턴 연장)

| 컴포넌트 | 책임 |
|---|---|
| `addr_building_coords` 테이블 + 마이그레이션 | 좌표사전. `building_mgmt_no`(PK 25자), 도로명 구조화 키 컬럼, `lat`,`lng`(WGS84 변환 후 저장), `loaded_at`. 수집기 alembic |
| 반입 적재 스크립트/태스크 | 내비게이션용DB TXT 파싱 → `pyproj`(5179→4326) 변환 → upsert. 전체분 1회 + 월간 변동분 동일 경로 |
| `geocode_complexes_task` (step2 §7 자리) | `complexes WHERE lat IS NULL AND kb_complex_id IS NOT NULL` → A/B/C 조인 → `UPDATE lat/lng`. 반환: `{matched_a, matched_b, matched_c, unmatched}` — 매칭률 가시화 |
| 의존성 | `pyproj` 추가 (oracledb 와 함께 requirements 반영) |

운영 플로우(월간): 외부망 PC에서 변동분 다운로드 → 사내 반입 절차 → 적재 태스크 → `geocode_complexes_task` 재실행(신규 단지 백필).

## 5. 미매칭 fallback — 법정동 중심좌표 근사 (✅ 확정: 미적용, 2026-06-04)

코드 실측(lat/lng 소비처 전수): 오차 수백 m~2km 근사를 넣으면 —

| 기능 | 영향 |
|---|---|
| 인근 유사물건 탐색 (`real_data_service.py:597-645`, 1→2km 반경 + 거리 30% 가중) | 후보 누락·**유사도 점수 왜곡** (부분 동작) |
| 지도 마커 (leaflet `NearbyPropertyMap.tsx`) | 핀이 실제 단지와 어긋남 — 사용자 체감 오류 |
| 입지점수 (`location_score_service.py`) | **무영향** — `facility.distance_m` 사전계산값 사용 |
| AI 분석 프롬프트 | **무영향** — facility 데이터만 사용 |

**확정: 미적용** — lat NULL 유지 시 인근동향은 해당 단지에서만 정직하게 비활성(`target_lat` None 체크 후 반환, 이미 안전 degrade). 심사 서비스에서 왜곡된 유사단지 점수보다 빈 상태가 낫다. SGIS centroid 원천은 채택하지 않음(§2 표는 조사 기록으로 유지). 건물관리번호 조인 매칭률 확인 후 미매칭이 유의미하게 남으면 재논의.

## 6. 선결 확인 (행정·probe — 이 환경에서 검증 불가)

1. **행안부 데이터 신청·승인**: 회사 명의 신청서 + 이용목적 심사 (1순위 경로의 전제. 행정 리드타임 존재).
2. 내비게이션용DB **레이아웃에 건물관리번호 필드 포함 여부** — 신청 후 제공 명세로 확인(미포함 시 B/C 키로 조인).
3. Oracle 실테이블 `ROAD_NM_BLDG_MGMT_NO` **채움률** probe(샘플 19행은 전수 채움, 전국 단위 확인 필요).
4. 폐쇄망 파일 반입 보안 절차·월간 운영 담당.
5. (✅ 확정) 지도 **타일서버**: 사용자 결정 — **지도 표시는 필수 아님**(2026-06-04). 사내 타일서버 검토 불요, 폐쇄망에선 지도 배경 없이(회색/비활성) 운영. 좌표의 가치는 인근동향 거리계산·목록으로 한정.
